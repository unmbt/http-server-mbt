# Node WasmGC 静态服务实施与验证（2026-10-13）

关联 R-N10/R-SAFE/R-N14、D-13、T-029、N-15/N-19/N-20。T-029 保持**进行中**：Windows 本机分项已验证，Linux/macOS 与远程三平台 Actions 证据尚未取得。

## 实现

- `internal/static_plan` 是 Native 与 Wasm 共用的静态决策状态机，负责表示选择、条件请求、Range、路由回退和目录渲染；不依赖 Native I/O 或 async Wasm 实现。根 Native 公共接口保持不变。
- `wasm` 导出真实 WasmGC 模块和版本化 JSON 控制桥接。文件元数据使用明确复制的字段，64 位偏移/长度使用十进制字符串，不经过 JS Number。正文文件字节由宿主按指定区间读取，默认块大小 64 KiB。
- [示例](../examples/wasm-node/README.md) 提供独立 ESM 文件宿主、类型声明、`createEngine`、`handle`、`close` 和 `node:http` 服务。应用无需 pump/poll，运行时不加载 `.node`。
- 请求和文件 ID 单调递增、不复用，耗尽拒绝接纳；操作序号拒绝重复/迟到完成。取消及关闭等待在途操作、文件关闭和正文 close 通知后返回。Readable 背压停止后续读取，并按预算限制连接、排队操作、正文和目录元数据。
- Wasm 宿主只承诺部署者控制的目录结构，拒绝 symlink/junction；恶意并发替换目录结构不在安全承诺内。文件内容更新仍支持检查与 `HS_FILE_CHANGED` 中止，不能当正常 EOF 或拼接重试。

## 测试范围与剩余验收

首次远程运行 [38376725796](https://github.com/unmbt/http-server-mbt/actions/runs/38376725796) 在 Windows/Linux/macOS 均因 `expected Moon 0.1.20260920` 失败，尚未执行到 Wasm 验收。根因为 `setup-moonbit` 未配置版本，默认下载最新工具链/core。修复将候选、汇总、发行及开发环境入口统一固定为已验证的发行版本 `0.10.14+7d59c7ec9`，保留原有门槛；已核对 action 的两个输入名，三平台工具链和 zip/tar.gz core 的官方下载地址均返回 HTTP 200。修复后远程结果需重新推送取得，不能将本次失败记录视为三平台通过。

修复验证：actionlint 1.7.12 检查上述三个 workflow 通过（`-shellcheck= -pyflakes=`，只检查 Actions/YAML 结构与表达式），`git diff --check` 通过。本次只改安装配置及证据文档，未重跑无关功能测试。另尝试下载 Windows 全量工具链以独立核对归档内容，但 120 秒网络超时，未作为验证通过；本机现有 `moon version --all` 已记录对应编译器与 Moon 版本。

共享 planner 在 Native/wasm-gc 上执行相同 fixtures，断言状态、头、文件区间与目录正文。候选驱动另启一个进程，针对相同真实文件向 Native addon 与 Wasm 提交 56 个请求，比较状态、全部响应头和原始正文；覆盖 gzip/Brotli、目录、BaseURL/SPA、Next、认证、HEAD/缓存/Range 与路径拒绝。独立 Wasm 验收进程不加载 addon。Node 集成另外覆盖真实 Wasm imports/ABI、HTTP、配置拒绝、短读、慢消费、截断、同长度修改、AbortSignal、HTTP 断连、多实例、预算耗尽、重复/迟到完成及关闭屏障。保存的种子及最小竞态步骤见 [Wasm 语料](../testdata/wasm/README.md)。这些证据不是全部原版迁移案例的跨宿主差分矩阵。
